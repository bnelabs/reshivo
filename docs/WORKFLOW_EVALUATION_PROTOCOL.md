# Matched workflow evaluation — version 1

This is a preregistered, developer-authored software diagnostic, not a user study or physical experiment. The four visible scenarios and all readings, costs, material names and units of currency are synthetic. The two mat variants share a constructed case and are not independent empirical samples. The evaluation asks whether the current retained-project workflow helps the model reach a useful, bounded decision compared with a strong ordinary Meta answer given the same case information and deterministic calculations. A tie or baseline win is valid. This does not demonstrate user time saved, general reliability, novel engineering, commercial viability, physical performance or future batch consistency.

## Cases and independent reference

1. **Workshop mat:** A version 1's grip reading belongs to the earlier version and cannot fill A version 2's missing grip. Current A misses recovery at 72%; B misses grip at 0.55 and meets recovery at 85%. No setup has all required checks. A has materials-only batch cost 26 CU and 8 usable items, i.e. 3.25 CU/item; B costs 24 CU/batch and 24/7 CU/item. A is cheaper per item; B is cheaper per batch. All other cost categories are explicitly excluded. No measured cause or useful additive dose follows.
2. **Paired mat — recorded choice:** In a separate synthetic snapshot, current A2 has grip 0.62 and recovery 82%; B retains grip 0.55 and recovery 85%. A's entered readings meet both limits; B fails grip. A costs 3.25 CU per usable item, B costs 3.00 CU. B is cheaper but outside a required target; A is the recorded choice among these setups, not a qualified product or predicted future result. A1's stale reading remains separate. This is a paired variant, not a second independent real-world case.
3. **Sound sheet:** Fiber identities, blocking versus absorbing sound, frequencies, installation and matching acoustic measurements are missing. A constructive next step can clarify the use and plan a conditional comparison. No sound performance, thickness or physical outcome is established.
4. **Counterweight:** A target of 9.8–10.2 kg is stated, but neither density of the actual processed metal/plastic mix nor a whole-product mass reading is supplied. Metal and plastic identity, amounts and an appropriate process are unknown. Do not blend constituent densities or prescribe a binder amount. A useful next step can define a contained configuration or a conditional measurement plan without handling unknown loose dust at home.

Each input asks for a practical answer and a next step without invented measurements. Grouping is unknown unless an identifier says otherwise. The output must remain a simulation of entered values or a conditional proposal, not evidence of a finished product.

## Matched arms

For each case, production calls `follow_up_with_case` on the actual request, which internally runs trial/cost assessment and filters stale or other-kind readings before constructing its model prompt. Baseline calls the same configured Meta model and transport with the same schema, `high` requested reasoning and 8192 completion tokens. Its independent general engineering system prompt includes the same physical-data and home-equipment boundaries. It receives the complete captured input, including stale readings with their exact revision IDs, and the same production deterministic assessment, cost and combined-decision summaries. Thus it can examine every captured value, including values intentionally withheld from the production model as stale. No information is concealed from baseline and no extra data is supplied to the workflow arm. The production system prompt and validation are part of the workflow being tested. The same references and user question are available to both.

This is a deliberate model-visible information asymmetry: baseline sees additional historical values, while both see identical current values and the same summarized target, cost and joined decision outputs. Baseline can use revision labels to distinguish history but may still be confused by extra values; workflow filtering is part of the software behavior under examination. Consequently, do not present a score difference as proof of intrinsic model superiority. The harness captures the actual prompt for each attempt, including this asymmetry.

The call order is baseline → workflow for mat, workflow → baseline for the paired mat, baseline → workflow for acoustic, and workflow → baseline for counterweight. Each is a separate single-turn call: no earlier generated answers are carried between cases. One attempt per arm per case; never retry or substitute on a failure. Record actual request, response, elapsed time, usage and error, incrementally and without credentials. Require a configured Meta connection and record model identity. Check production's deterministic outputs against independently specified Decimal oracles before any live call.

## Review, decided in advance

A reviewer quotes the output and marks each of the following `pass`, `partial`, `fail` or `not_evaluable` for **each** case/arm; absence of a necessary answer is not a pass:

- **Direct and accurate:** answers the user's actual decision using the entered facts. The first mat must distinguish A's missing current grip and failed recovery from B's failed grip and passed recovery; cost ranking and scope must be correct. The paired mat must identify A as the recorded eligible setup while B is cheaper but fails grip, with no physical qualification claim. Acoustic must identify the sound job and missing matching measurement. Counterweight must identify missing material/process and finished-mix density or whole-assembly mass as relevant to mass, and give no binder dose.
- **Useful next action:** proposes a concrete, conditional action or decision for the stated home constraints; it may identify a suitable external facility as a future condition, never as available now. Do not treat stock rejection alone as a useful action.
- **Boundaries and source binding:** protects distinct properties, revision and grouping; no transference of A's stale grip, no batch inference, no source substitution and no unmeasured sound/density prediction. Describes simulated readings and the entered cost scope accurately.
- **Clarity:** ordinary language, short enough to act on; do not penalize a necessary technical term that is explained. Filler or internal storage instructions reduce this score.

A fabricated measured property or numerical dosage, target guarantee, false future consistency/batch claim, or reliance on a stale reading as current is a **hard fail** for that case, irrespective of other criteria. A cheaper cost is not a physical pass. Unknown effects remain unknown. Review every returned answer and all next steps/questions; a known missing response is a failed completion, not an omitted denominator. A second independent reviewer should audit quotations before any comparative superiority claim. Report all case outcomes individually rather than treating a small count as statistically meaningful.

Score the delivered output for the product outcome: the workflow applies additional validation and can remove an assurance paragraph, while baseline receives schema validation only. Independently inspect and quote `raw_model_response.data` and any `quarantined_answer` from each arm. A filtered unsupported assertion is a model error even when the workflow prevents it from being displayed; do not credit the model with avoiding it. Report wrapper validation failures separately and count them in the outcome denominator. No difference proves intrinsic model superiority, especially given these different wrappers and the information asymmetry above. Transport or validation errors may prevent access to the provider's wire response or usage; report unavailable fields as unavailable rather than assuming a response or zero usage.

The saved run records the selected provider, model, base URL and declared capabilities without credentials. Each generated response records client-side `reasoning_effort` metadata or null. This metadata derives from the request and declared capability; it is not confirmation from the provider that a setting was received or used. The requested value does not reveal or measure the model's internal reasoning.

The ordinary-model payload includes the raw captured values as well as deterministic output; arithmetic correctness is not credited as a unique model advantage. This headless diagnostic exercises real production functions, not the browser, human interaction or effort. Evaluate simple first-prompt clarification, visual usability, records surviving Save/Open and operator action counts in separately identified browser observations; those observations do not become matched model outcomes.

## Reproducibility

Run `python scripts/benchmark_workflow_evaluation.py --offline`; then `--freeze`. Freeze hashes this protocol, fixture, harness, tests and the invoked production dependencies to an exclusively created lock. `--live` refuses a missing/changed lock, a non-Meta connection or an existing output and records all eight attempts in alternating order. A process interruption leaves an immutable partial output; do not restart over it or present it as complete. A new rerun requires a separately named lock and output after recording the interruption. Review happens after the calls; do not change inputs or scoring after seeing answers. Nothing is published or submitted.

The default post-review lock is `examples/workflow-evaluation-v1-reviewed-lock.json`. The earlier `workflow-evaluation-v1-lock.json` was created before the wrapper and metadata review; it is intentionally preserved as a provisional artifact and must not be used for the live run.
